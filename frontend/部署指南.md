## 一、环境准备

### 1.1 安装 Node.js

```bash
# 检查 Node.js 版本（需要 ≥ 18）
node --version
# 输出: v18.x.x 或 v20.x.x

# 检查 npm 版本
npm --version
```

**下载地址**：https://nodejs.org/ （建议安装 LTS 20.x 版本）

### 1.2 安装 pnpm（推荐）

```bash
# 使用 npm 安装 pnpm
npm install -g pnpm

# 验证
pnpm --version
# 输出: 9.x.x
```

### 1.3 进入项目目录 & 安装依赖

```bash
# Windows PowerShell
cd E:\web\myweb\frontend

# Linux / macOS
cd /var/www/myweb/frontend

# 安装依赖
pnpm install

# 安装完成后，node_modules/ 目录已生成
```

### 1.4 目录结构说明

```
frontend/
├── public/                  # 静态资源（直接复制到构建目录）
├── src/                     # 源码
├── index.html               # HTML 入口
├── vite.config.ts           # Vite 构建配置
├── tsconfig.json            # TypeScript 配置
├── package.json             # 依赖与脚本
├── .env.development         # 开发环境变量
├── .env.production          # 生产环境变量
├── 部署指南.md               # 本文件
└── dist/                    # 构建产物（运行 pnpm build 后生成）
```

## 二、本地开发

### 2.1 启动开发服务器

```bash
# 确保在 frontend 目录
cd E:\web\myweb\frontend

# 启动 Vite 开发服务器（热重载）
pnpm dev
```

启动成功后看到：

```
VITE v5.x.x  ready in xxx ms
  ➜  Local:   http://localhost:3000/
  ➜  Network: http://192.168.x.x:3000/
```

### 2.2 开发环境特性

| 特性 | 说明 |
|------|------|
| **热重载 (HMR)** | 代码修改后浏览器自动刷新 |
| **API 代理** | `/api` 请求自动转发到 `http://localhost:8000`（后端） |
| **TypeScript 检查** | IDE 中实时类型检查 |
| **Element Plus** | 按需引入，组件自动注册 |

### 2.3 开发环境代理配置

`vite.config.ts` 中的代理配置：

```typescript
server: {
  port: 3000,
  proxy: {
    '/api': {
      target: 'http://localhost:8000',  // 后端地址
      changeOrigin: true,
    },
  },
}
```

这样前端开发时请求 `/api/v1/auth/login` 会自动代理到 `http://localhost:8000/api/v1/auth/login`，无需配置 CORS。

### 2.4 同时启动前后端

```powershell
# 终端 1：启动后端
cd E:\web\myweb\backend
.\venv\Scripts\Activate.ps1
uvicorn main:app --reload --port 8000

# 终端 2：启动前端
cd E:\web\myweb\frontend
pnpm dev
```

然后访问 http://localhost:3000 即可。

## 三、构建生产包

### 3.1 配置生产环境变量

编辑 `.env.production`：

```env
# .env.production
VITE_API_BASE_URL=https://your-domain.com/api/v1
VITE_ENV=prod
```

> **注意**：`VITE_API_BASE_URL` 必须是完整的后端 API 地址（含 `/api/v1` 前缀）。

### 3.2 执行构建

```bash
cd E:\web\myweb\frontend

# 方式一：使用 pnpm
pnpm build

# 方式二：使用 npm
npm run build
```

### 3.3 构建产物

构建完成后，生成 `dist/` 目录：

```
dist/
├── index.html
├── assets/
│   ├── index-xxxx.js        # 主 JS 文件（含代码分割）
│   ├── index-xxxx.css       # 主 CSS 文件
│   └── vendor-xxxx.js       # 第三方库（Element Plus 等）
└── favicon.ico              # 如果有
```

> **说明**：`xxxx` 为内容哈希值，每次构建不同，用于缓存控制。

### 3.4 预览构建产物


## 四、Nginx 部署（Linux 服务器）

### 4.1 上传构建产物

```bash
# 本地打包 dist 目录
cd E:\web\myweb\frontend
tar -czf frontend-dist.tar.gz dist/

# 上传到服务器
scp frontend-dist.tar.gz root@你的服务器IP:/var/www/myweb/

# 在服务器上解压
ssh root@你的服务器IP
cd /var/www/myweb
tar -xzf frontend-dist.tar.gz
mv dist frontend
```

### 4.2 安装 Nginx

```bash
# CentOS / Alibaba Cloud Linux
yum install -y nginx
systemctl enable nginx
systemctl start nginx

# Ubuntu / Debian
apt install -y nginx
systemctl enable nginx
systemctl start nginx
```

### 4.3 配置 Nginx

```bash
vim /etc/nginx/conf.d/myweb.conf
```

```nginx
# HTTP → HTTPS 重定向
server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$server_name$request_uri;
}

# HTTPS Server
server {
    listen 443 ssl http2;
    server_name your-domain.com;

    # SSL 证书（使用 Let's Encrypt 或阿里云免费证书）
    ssl_certificate     /etc/nginx/ssl/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/your-domain.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    # Gzip 压缩
    gzip on;
    gzip_types text/plain text/css application/json application/javascript image/svg+xml;
    gzip_min_length 1024;
    gzip_vary on;

    # 根目录指向前端构建产物
    root /var/www/myweb/frontend;
    index index.html;

    # 静态资源缓存（带 hash 的文件长期缓存）
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
        access_log off;
    }

    # API 反向代理到后端
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }

    # Admin 后台（与 API 共用后端）
    location /admin/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # SPA 路由：所有非文件请求返回 index.html
    location / {
        try_files $uri $uri/ /index.html;

        # HTML 文件不缓存
        location = /index.html {
            add_header Cache-Control "no-cache, must-revalidate";
        }
    }

    # 日志
    access_log /var/log/nginx/myweb-access.log;
    error_log  /var/log/nginx/myweb-error.log;
}
```

### 4.4 关键配置说明

| 配置项 | 作用 |
|--------|------|
| `root /var/www/myweb/frontend` | 指向构建产物目录 |
| `try_files $uri $uri/ /index.html` | SPA 路由支持（所有路径返回 index.html） |
| `location /assets/` | 静态资源长期缓存（1 年） |
| `location /index.html` | HTML 不缓存 |
| `location /api/` | API 请求反向代理到后端 |
| `gzip on` | 启用 gzip 压缩 |

### 4.5 部署后端 API

如果后端在同一台服务器，参考 `backend/部署文案.md` 部署后端。

**前后端同机部署架构**：

```
用户 → Nginx (443) → /api/* → localhost:8000 (FastAPI)
                    → /*      → /var/www/myweb/frontend (静态文件)
```

### 4.6 验证部署

```bash
# 检查 Nginx 配置
nginx -t

# 重新加载 Nginx
systemctl reload nginx

# 测试访问
curl -I https://your-domain.com
# 应返回 200 OK

curl -I https://your-domain.com/api/v1/health
# 应返回 200 OK
```

## 五、Nginx 部署（Windows 服务器）

### 5.1 构建生产包

```powershell
cd E:\web\myweb\frontend
pnpm build
```

### 5.2 安装 Nginx for Windows

```powershell
# 前往 https://nginx.org/en/download.html 下载 Windows 版
# 解压到 C:\nginx

# 目录结构：
# C:\nginx\
#   ├── nginx.exe
#   ├── conf/nginx.conf
#   └── html/          # 默认网站根目录
```

### 5.3 配置 Nginx

```powershell
# 编辑 C:\nginx\conf\nginx.conf
```

```nginx
worker_processes  1;

events {
    worker_connections  1024;
}

http {
    include       mime.types;
    default_type  application/octet-stream;

    gzip on;
    gzip_types text/plain text/css application/json application/javascript;

    server {
        listen       80;
        server_name  localhost;

        # 前端构建产物目录
        root   E:/web/myweb/frontend/dist;
        index  index.html;

        # 静态资源缓存
        location /assets/ {
            expires 1y;
            add_header Cache-Control "public, immutable";
            access_log off;
        }

        # API 反向代理到后端
        location /api/ {
            proxy_pass http://127.0.0.1:8000;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        }

        location /admin/ {
            proxy_pass http://127.0.0.1:8000;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        }

        # SPA 路由
        location / {
            try_files $uri $uri/ /index.html;
        }
    }
}
```

### 5.4 启动 Nginx

```powershell
# 测试配置
cd C:\nginx
nginx -t

# 启动 Nginx
start nginx

# 或
nginx.exe

# 重新加载配置
nginx -s reload

# 停止
nginx -s stop
```

### 5.5 访问测试

```powershell
# 打开浏览器访问
http://localhost

# 测试 API
curl http://localhost/api/v1/health
```

## 六、Docker 部署（可选）

### 6.1 创建 Dockerfile

```dockerfile
# frontend/Dockerfile
FROM node:20-alpine AS builder

WORKDIR /app

# 安装 pnpm
RUN npm install -g pnpm

# 复制依赖清单并安装
COPY package.json pnpm-lock.yaml ./
RUN pnpm install --frozen-lockfile

# 复制源码并构建
COPY . .
RUN pnpm build

# ── 运行阶段 ──
FROM nginx:alpine

# 复制构建产物
COPY --from=builder /app/dist /usr/share/nginx/html

# 复制 Nginx 配置
COPY nginx.conf /etc/nginx/conf.d/default.conf

EXPOSE 80

CMD ["nginx", "-g", "daemon off;"]
```

### 6.2 创建生产 Nginx 配置

```nginx
# frontend/nginx.conf
server {
    listen 80;
    server_name _;

    root /usr/share/nginx/html;
    index index.html;

    gzip on;
    gzip_types text/plain text/css application/json application/javascript;

    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    location /api/ {
        proxy_pass http://backend:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

### 6.3 构建与运行

```bash
# 构建镜像
docker build -t myweb-frontend .

# 运行容器
docker run -d \
  --name myweb-frontend \
  -p 80:80 \
  myweb-frontend
```

### 6.4 docker-compose 部署（前后端一起）

```yaml
# docker-compose.yml
version: '3.8'

services:
  backend:
    build: ./backend
    ports:
      - "8000:8000"
    environment:
      - APP_ENV=prod
      - DATABASE_URL=postgresql+asyncpg://postgres:postgres@db:5432/myweb
    depends_on:
      - db
      - redis

  frontend:
    build: ./frontend
    ports:
      - "80:80"
    depends_on:
      - backend

  db:
    image: postgres:15
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
      POSTGRES_DB: myweb
    volumes:
      - pgdata:/var/lib/postgresql/data

  redis:
    image: redis:7

volumes:
  pgdata:
```

## 七、环境变量与 API 代理

### 7.1 环境变量说明

| 变量名 | 开发环境 | 生产环境 | 说明 |
|--------|----------|----------|------|
| `VITE_API_BASE_URL` | `/api/v1` | `https://api.your-domain.com/api/v1` | API 基础路径 |
| `VITE_ENV` | `dev` | `prod` | 环境标识 |

### 7.2 不同部署方式的 API 地址

| 部署方式 | VITE_API_BASE_URL | 说明 |
|----------|-------------------|------|
| 本地开发（代理） | `/api/v1` | Vite 代理到 localhost:8000 |
| 同机 Nginx | 无需设置或留空 | Nginx 反向代理 /api → 后端 |
| 前后端分离 | `https://api.your-domain.com/api/v1` | 直接请求后端域名 |
| Docker Compose | 无需设置 | Nginx 通过内部网络连接 backend:8000 |

### 7.3 跨域配置（前后端分离时）

如果前后端部署在不同域名，需要在后端 `main.py` 中配置 CORS：

```python
# backend/main.py（已配置）
app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://your-frontend-domain.com"],  # 改为具体域名
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

## 九、常见问题排查

### 9.1 页面空白 / 404（刷新时）

**症状**：访问 `/experts` 正常，但刷新后 404。

**原因**：Nginx 未配置 SPA 路由支持。

**解决**：确保 Nginx 配置中有：

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

### 9.2 API 请求 502

**症状**：页面加载但数据为空，控制台显示 API 502。

**原因**：后端未启动或 Nginx 代理配置错误。

**解决**：

```bash
# 检查后端是否运行
curl http://127.0.0.1:8000/health

# 检查 Nginx 代理配置
nginx -t

# 检查后端日志
sudo journalctl -u myweb-api -n 50
```

### 9.3 API 请求 404

**症状**：请求 `/api/v1/xxx` 返回 404。

**原因**：`VITE_API_BASE_URL` 配置错误或 Nginx 代理路径不匹配。

**解决**：

```bash
# 确认前端请求的 URL
# 浏览器 DevTools → Network 查看实际请求地址

# 确认 Nginx 代理目标地址正确
# proxy_pass http://127.0.0.1:8000;  # 注意末尾不要有 /api
```

### 9.4 跨域错误 (CORS)

**症状**：浏览器控制台显示 `Access-Control-Allow-Origin` 错误。

**原因**：前后端分离部署时，后端未配置 CORS。

**解决**：

```bash
# 方案 A：使用 Nginx 同一域名部署（推荐）
# 前端和后端共用 Nginx，/api/ 代理到后端

# 方案 B：后端配置 CORS
# 在 main.py 中设置 allow_origins 为前端域名
```

### 9.5 构建失败

```bash
# TypeScript 类型错误

```

### 9.6 代理不生效（本地开发）
